# 적용한 VLAN·라우팅·방화벽 규칙

## Firewall — 172.16.255.2

`eth1.131/132/133`을 생성하고 각각 `10.10.131/132/133.1/24`를 부여했다. 스위치의 기존 VLAN access/trunk 값은 이미 문서와 일치했다. Firewall의 default via `10.99.143.1`, C4I 라우터의 `10.10.128.0/21 → 10.99.143.2`, 기존 OSPF는 유지한다.

`inet astra_cso`라는 독립 테이블을 만들었다. 기존 nft filter/NAT 및 관리 INPUT/OUTPUT는 그대로 둔다. forward priority -50에서 C↔C와 C↔S를 허용하고 나머지 C 송수신을 drop한다. 각 C4I VLAN의 source prefix 위조와 routed IPv6도 drop한다. established 연결이라고 먼저 허용하지 않으므로 기존 C↔O 세션도 차단된다.

| 로컬 파일 | 실제 장비 경로 |
| --- | --- |
| `규칙/firewall-vlans.sh` | `/etc/sonar_validator_prober/cso-vlans.sh` |
| `규칙/firewall-cso.nft` | `/etc/sonar_validator_prober/firewall-cso.nft` |
| `규칙/firewall-cso-apply.sh` | `/etc/sonar_validator_prober/cso-apply.sh` |

`/root/start.sh`에서 agent 시작 전에 `cso-apply.sh`를 실행한다. nft 문법 검사를 통과한 뒤 우리 테이블만 atomic transaction으로 교체하고 VLAN을 활성화한다. 전체 ruleset flush는 사용하지 않는다.

## Gateway-Router — 172.16.255.1

`ASTRA_CSO_WAN` 독립 iptables 체인을 FORWARD 첫 위치에 연결했다. C4I 3개 /24와 Firewall 전송망 `10.99.143.0/24`의 WAN eth0 송수신을 drop한다. 후자는 기존 Firewall MASQUERADE로 주소가 바뀌는 경우를 포함한다. 기존 NAT·OSPF·관리 INPUT/OUTPUT는 유지한다.

`규칙/gateway-cso.sh`를 `/etc/sonar_validator_prober/cso-gateway.sh`에 설치했다. `/etc/local.d/astra-cso.start`가 이를 실행하며 OpenRC local 서비스를 default runlevel에 등록했다. Firewall이 1차 집행 지점이고 Gateway는 인터넷 경계의 추가 차단 지점이다.

## 재적용

```sh
# Firewall에서
sh /etc/sonar_validator_prober/cso-apply.sh
nft list table inet astra_cso

# Gateway에서
sh /etc/sonar_validator_prober/cso-gateway.sh
iptables -nvL ASTRA_CSO_WAN
```

## 복구

이번 ACL만 되돌리는 스크립트는 `규칙/rollback-firewall.sh`, `규칙/rollback-gateway.sh`다. 각 해당 장비에 전달해 실행한다. VLAN 복구는 유지하며 기존 방화벽 테이블·NAT·OSPF를 삭제하지 않는다. **복구하면 C↔Open/인터넷의 기존 허용 상태로 돌아갈 수 있다.**

배포 전 파일은 장비별 `/root/astra-cso-before-20261009/`에 보관했다. VLAN까지 배포 전 상태로 되돌려야 한다면 Firewall의 `eth1.131/132/133`을 삭제하고 백업의 `/root/start.sh`, `/etc/network/interfaces`를 복구한다. 이는 C4I 게이트웨이를 제거하는 별도 조치이므로 이번 작업 종료 상태에서는 실행하지 않는다.

## 백엔드 집행 모드

직접 관리하는 ACL과 에이전트의 주기적 정책 생성이 충돌하지 않도록 `.env`의 `SONAR_POLICY_AUTOMATIC_ENFORCEMENT_ENABLED=false`를 적용했다. 수집·터미널·BDD 검증은 동작하고 자동 policy-request 응답은 `source=external-enforcement`, `policies=[]`다. 명시적 격리 override는 유지한다. 자동 정책 집행으로 전환할 때는 직접 ACL과 생성 정책을 함께 검토하고 이 설정을 바꿔야 한다.
