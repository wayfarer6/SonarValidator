# 수정사항과 발견한 문제

이번 회차는 실제 CSO 적용·BDD·재기동 검증 과정에서 재현한 문제를 수정했다. 이전 에이전트 배포 회차의 WebSocket 반복 수집·터미널 URL·VLAN 편집 수정은 상위 README에 기록되어 있다.

| 구성 요소 | 재현된 문제 | 수정 |
| --- | --- | --- |
| Backend BDD | 큰 Sensitive CIDR 내부의 Confidential→Open 위반이 내부 BDD에는 존재하지만 최종 compliant 판정에서 누락 | 등급 라벨에 따른 사전 제외 제거. 규칙과 금지 패킷 집합의 교집합으로 판정하고 반례가 속한 실제 금지 대역을 보고 |
| Prober nft 수집 | 이름 있는 set, interval, 집합 조건을 텍스트 grammar가 파싱하지 못해 적용된 ACL 누락 | `nft -j list ruleset`의 구조화된 원본을 우선 전송. 기존 text는 JSON을 얻지 못할 때 fallback |
| Backend nft 정규화 | 부분 파싱을 경고하지 않고, match 조건도 빠뜨려 규칙을 불완전하게 표시 | native nft JSON의 set/map/chain/rule 전체 보존. legacy parse 오류 경고, raw/match 조건 보존 |
| Backend 자동 집행 | 장비 출처를 가진 서브넷의 등급을 저장하면 주기적인 policy-request가 직접 적용한 ACL과 별개 명령을 실행 | `sonar.policy.automatic-enforcement-enabled` 옵션 추가. 이번 랩은 false, 기본값 true로 기존 환경 호환 |
| Frontend Agent | 마지막 수신에 등록 시각을 표시하여 재수집 여부를 잘못 표현 | 실제 discovered config의 `last_seen` 사용. 아직 수신이 없으면 빈 표시 |
| Firewall 부팅 설정 | `/etc/network/interfaces` 선언만 있고 실제 VLAN 서브인터페이스가 없어 C4I 게이트웨이 미동작 | idempotent VLAN 생성·ACL 적용을 부팅 스크립트에 연결 |
| 배포 재시작 | supervisor에 TERM 후 바로 start하면 기존 supervisor 종료 대기 중이라 start가 건너뛰어질 수 있음 | 회귀 재시작 스크립트가 이전 supervisor 종료를 확인한 다음 start하도록 처리 |

## 검증

BDD는 일반 C↔O·인터넷 금지, 인접 등급 허용, 동일 등급 허용, disabled 규칙, 포트 누락, 잘못된 포트, 중첩 CIDR을 시험한다. 중첩 CIDR은 Java 회귀에서 양방향 반례와 비중첩 정상 대조군도 검증한다.

Prober는 native JSON의 set·조건·counter·drop이 수집 결과에서 그대로 보존되는지 검사한다. Backend는 동일한 필드의 정규화와 legacy 부분 파싱 경고를 검사한다. 실제 장비에서도 전송 payload와 `nft -j list ruleset`의 규칙 comment·주소 집합을 대조한다.

수정 전 nft 누락 증거는 `firewall-after-acl-payload.json`, BDD 누락 증거는 `bdd-CIDR-overlap-before-fix.json`에 보존했다. 수정 전 실패 증거를 최종 성공 결과로 덮어쓰지 않는다.

## 남은 제한

- 임의 nftables/iptables의 전체 의미를 BDD로 자동 컴파일하는 기능은 구현하지 않았다. 실측 연결을 명시적으로 BDD에 넣은 이번 E2E와 구분해야 한다.
- `/etc/os-release`가 링크 경로가 든 일반 파일인 방화벽의 OS 표시 문제는 네트워크 설정과 별개로 남아 있다. nftables 제품 탐지·AlpineFirewall 파싱에는 영향이 없다.
- 종료된 Sensitive 업무 컨테이너의 애플리케이션 가용성은 검증하지 않았다. 동일 VLAN의 임시 probe로 데이터 경로를 검증했다.
