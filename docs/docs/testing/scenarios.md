# 회귀 시나리오

기존 데이터와 네트워크를 보존한 상태에서 확인합니다. 아래 시험 계획과 실제 실행 결과는 구분합니다.

| 단계 | 기대 결과 |
| --- | --- |
| 서버 | 기존 프로젝트 유지, health UP |
| SSH | R1·R2 BatchMode 키 접속 |
| 번들 | 이름·Router 유형·관리 주소·포트·공유 키 일치, 호환 바이너리 포함 |
| 설치 | Cisco 프로필, guestshell 사용자, 영속 경로, 서비스 enable |
| 연결 | 프로젝트의 두 Agent connected |
| 반복 수집 | last_seen 증가, IOS 인터페이스·라우트 수집 |
| 편집 | CIDR·등급·담당·허용 연결 저장 후 재조회 일치 |
| 검증 | 등급 금지 관계와 미분류 입력을 기대대로 판정 |
| 적용 | 명시적 정책 실험에서 응답과 실제 장비 상태 비교 |
| 재기동 | 재기동한 구성 요소와 자동 복구 범위를 기록 |

Lab 1은 배포와 수집을 먼저 검증합니다. 정책 푸시·격리·장애 주입은 별도 실험입니다.

## 이번 Lab1 실제 실행

새 Prober 정적 바이너리에서 Robot 기본 S01~S05 5개가 통과했습니다. S03 스트레스 모드의 장비별 10회, 총 20회 연결·종료가 통과했고, 활성 셸에서 Prober SIGTERM·임시 작업 제거·EEM 자동 복구를 확인하는 S06도 통과했습니다. 로컬 DB·PTY 회귀 검사는 `tests/prober/run.sh`에서 수행합니다. 실제 결과물은 작업 보고서와 Robot HTML 로그·영상에 보관합니다. Lab2~4는 프로젝트 미지정으로 SKIP입니다.
