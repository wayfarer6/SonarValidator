# 더미 출력 제거와 버그 수정

2026-11-01 · 더미 제거/버그 수정 단계의 검증 기록입니다. 이후 로그 변경과 최신 배포 상태는 [작업 중심 로그](./logging.md)를 따릅니다. Git 커밋·푸시·릴리즈는 수행하지 않았습니다.

## 변경 결과

| 영역 | 문제와 변경 |
| --- | --- |
| Backend 출력 | `/api/v1/cli/targets`의 하드코딩된 route 예시를 제거했습니다. 실제 지원 명령·벤더 정보는 유지합니다. 주기적인 수집/ACK 로그는 DEBUG로 내렸습니다. |
| CLI 결과 판정 | 파싱 결과가 0건인데 `accepted=true`로 응답하던 모순을 수정했습니다. 오류 목록과 accepted가 같은 판정을 사용합니다. |
| 오프라인 가져오기 | 검증이 끝나기 전에 Store와 Observer를 변경하던 경로를 수정했습니다. 거부 파일은 기존 설정·원본·출처를 유지합니다. |
| 입력 크기 | 전체 스트림을 읽은 뒤 크기를 검사하던 처리를 8 MiB + 1 byte 제한 읽기로 바꿨습니다. |
| 부분/실패 수집 | 마지막 정상 항목이 누락되거나 파싱 실패이면 정상 설정을 유지하고 동기화 Observer를 호출하지 않습니다. 첫 수집도 파서 능력에 필요한 항목이 부족하면 자동 서브넷을 갱신하지 않습니다. |
| 관측 보존 | 정상 payload·중립 설정·오프라인 출처를 하나의 accepted record로 관리합니다. 최신 수신 원문은 별도 진단 정보이며 정상 관측을 의미하지 않습니다. |
| API 권한 | VIEWER의 프로젝트·정책·격리·Agent 변경을 거부합니다. 번들에는 접속 자격증명이 포함되므로 다운로드도 ADMIN/OPERATOR로 제한합니다. 조회·비저장 검증·본인 계정 처리는 허용합니다. |
| 암호화 | 잘못되거나 없는 영구 키를 임시 키로 대체하는 동작을 제거했습니다. Backend 시작 시 키 형식을 검사하며 기존 Lab 키는 그대로 유지했습니다. |
| 설정 UI | 노드 변경 시 폼 상태를 초기화합니다. 연결 저장 중 입력/닫기/삭제를 잠그고 저장 후 상위 목록을 갱신합니다. 수집 주기도 저장 중 입력을 잠급니다. |
| 화면 이동 | 다운로드 페이지를 직접 열어도 닫기 버튼이 해당 프로젝트 편집으로 이동합니다. 서버 설정 오류는 입력 수정 시 해제합니다. |
| 템플릿 정리 | 제품과 무관한 12개 데모 경로, 예시 소스 40개, 사용하지 않는 직접 의존성 11개를 제거했습니다. npm 트리에서는 22개 패키지가 줄었습니다. 남아 있던 TailAdmin 페이지 메타데이터도 제품 문구로 바꿨습니다. |
| 생성 산출물 | 작업트리에서 `.class`와 `:Zone.Identifier`를 제거하고 ignore 규칙을 추가했습니다. 실제 파일 삭제 555개이며 Git 삭제 차이는 314개 클래스·258개 메타데이터 경로입니다. 정상 소스·테스트 fixture·ANTLR 소스·운영 DB는 보존합니다. |

테스트 전용 데이터와 모의 AI 공급자는 테스트 경로에 유지합니다. BDD의 `sampled_packet` 등은 실제 정책 반례이므로 제거하지 않았습니다. 실제 서비스 응답에 테스트용 결과를 넣는 기능을 추가하지 않았습니다.

## 검증

| 검사 | 결과 |
| --- | --- |
| Backend 전체 Maven 테스트 | 526건 통과, 실패/오류/skip 0 |
| Frontend 테스트 | 14건 통과. 실제 React 컴포넌트의 지연 저장·노드 변경·본문 timeout 포함 |
| Frontend 빌드·lint | 성공, lint 오류 0. 기존 Fast Refresh 경고 7개와 번들 크기 안내는 남아 있습니다. |
| Robot B01~B03 | 3/3 통과. CLI 예시 제거·데모 경로 404, 지연된 연결 저장 보호, 프로젝트 복귀를 실제 UI로 확인 |
| Lab 1 SSH·자동 실행 | R1/R2 모두 SSH 키 로그인 성공, Prober 각 1개·4 threads·idle children 없음 |
| Lab 1 실제 수집 | R1 인터페이스 5/라우트 9, R2 인터페이스 5/라우트 7. 둘 다 discoveryComplete=true, 수집 주기 30초 |
| 상태 보존 | 기존 4개 Lab 프로젝트·Expected Agent 10개 유지, 임시 Robot 프로젝트 제거, Lab 1만 실행 상태로 복원 |

Robot은 임시 프로젝트에서 실제 저장 요청을 잠시 지연시킨 후 서버에 반영합니다. 실제 장비 정책 push·격리 명령은 보내지 않았습니다. 시나리오마다 스크린샷·녹화가 생성됩니다. 재실행 명령은 `SONAR_UI_PASSWORD`를 환경에 설정한 뒤 `bash tests/robot/run.sh lab1 check regressions`입니다. `demo`로 바꾸면 발표용 속도를 사용합니다.

R2를 빌드 자원 확보를 위해 중지했다가 복원하여 SSH·기존 부팅 훅의 Prober 자동 실행·새 수집을 확인했습니다. 두 Prober의 바이너리는 기존 SHA-256 `11a44d31062e5f16fed0ed833df6d35b3f21288ea3b1f3646483edfdbfa74a13`와 같습니다. 이번에는 Prober 바이너리나 장비 설정을 변경하지 않았고 Lab 2~4 장비를 다시 부팅하지 않았습니다.

문서는 변경한 MDX의 구문과 로컬 링크를 검사합니다. 메모리 여유가 작은 실행 환경에서 전체 문서 사이트 빌드는 다시 수행하지 않습니다.

## 남은 검토 항목

[코드 검토 현황](./code-review.md)에 완료와 미완료를 구분했습니다. 장비 WebSocket의 노드별 인증/TLS, 여러 서브넷의 정책 계획, Prober 명령 수신·장비 ACL/격리 적용, 프로젝트 동시 편집 버전, SQLite 보존/완전한 스냅샷, DB migration은 별도 항목으로 열려 있습니다. 이번 테스트 통과를 이 항목들의 해결이나 실제 데이터 평면 차단 검증으로 해석하지 않습니다.

완전히 빈 수집만으로 기존 자동 서브넷 전체를 지우지 않습니다. 장비 철거는 운영자가 프로젝트에서 확인 후 정리합니다. 항목별 원본 관측 시각과 마지막 성공 시각을 UI로 제공하는 일도 남아 있습니다.
