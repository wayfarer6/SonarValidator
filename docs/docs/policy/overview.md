# 정책 모델과 편집 흐름

프로젝트는 서브넷과 연결 규칙을 가집니다. 수집된 인터페이스·VLAN은 초안입니다. 사용자가 이름·CIDR·등급·담당 Agent를 확인해 저장합니다.

## 서로 다른 분류

- 장비 유형: Router, Switch, Firewall, VM. 수집기와 적용기를 결정합니다.
- 네트워크 역할: 관리망, 전송망, 내부망, 인터넷 업링크. 운영 목적을 나타냅니다.
- 보안 등급: Confidential, Sensitive, Open. 검증에 사용하는 값입니다.

역할과 보안 등급을 같은 값으로 취급하지 않습니다. 특히 관리망을 일반 업무망처럼 분류해 차단하지 않습니다. [UI 검토](../frontend/lab1-review.md)도 참조합니다.

## 허용 연결

현재 `allowed_peers=[]`는 **제한 없음**입니다. 하나 이상 지정하면 목록 밖 상대의 차단 정책이 만들어집니다. 빈 목록을 전부 차단으로 해석하면 안 됩니다. Internet 대상과 프로젝트 내 서브넷 식별자를 구분하고 방향·프로토콜·포트·활성 여부를 함께 확인합니다.

## 검증과 적용

초안 편집 → 초안 검증 → 저장 → 배포 규칙·대상 검토 → 푸시 → 실제 적용 확인 순서입니다. `connected`는 ACL 적용 성공을 뜻하지 않습니다.

`SONAR_POLICY_AUTOMATIC_ENFORCEMENT_ENABLED=false`는 프로젝트 자동 집행을 중지합니다. 현재 `forDevice()`의 기본/외부 집행 선언은 `policies=[]`이므로 예제 장비 명령을 전송하지 않습니다. 운영자가 별도로 요청한 격리 상태의 동기화는 별도 경로입니다.

상세: [BDD 검증 범위와 Batfish 비교](bdd.md), [장비 계약](device-contracts.md).
